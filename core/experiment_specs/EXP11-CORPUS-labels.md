## 1. Question and hypotheses

Q1. How reliable are the existing automatic labels `primary_category` (NLP, 11 codes), `evidence_type` and `design` (both extracted by agents), measured against an independent gold set?
Q2. Can a classifier trained on embeddings or TF-IDF predict these labels, and does it agree with the gold set better or worse than the existing labels?
Q3. Which 40 articles should be labelled next, to improve the gold set most?

Expectation: `primary_category` has weak agreement with a careful human or LLM reading, because the NLP picks the organ system with most concept evidence, while a reader picks the organ system the study is about (the agent label already differs from the NLP label in 190 of 444 articles). A classifier trained on the automatic labels will reproduce them, including their mistakes, and will not beat them against the gold set. A negative finding (no classifier beats the existing labels on the gold set) is the likely and publishable result.

**State plainly in the interpretation: training on the automatic labels learns their mistakes. Cross-validated accuracy on the automatic labels measures reproducibility of the labelling rules, not correctness. The gold set is the point of the experiment; without it the result is circular.**

Not applicable. The gold set (section 3.2) is a new input file, not a tidy dataset.

### 2.3 Variables and filters

Three label targets, each normalised to a closed set (rules in 3.1):

- `primary_category`: 11 classes.
- `evidence_type_norm`: `descriptive`, `associational`, `prognostic`, `mechanistic`, `review`, `case_report`.
- `design_norm`: `case_report`, `review`, `case_control_or_cohort_natural`, `experimental_infection`, `cross_sectional_or_prevalence`, `diagnostic_or_molecular`, `treatment_trial`, `other`.

A class with fewer than 5 articles in the training labels is kept in the report but merged into `other_rare` for fitting (record this). Articles with a null label for a target are dropped for that target only (the 16 `category_confidence` null articles still have a `primary_category`).

## 3. Method

Defaults (all in `experiment.parameters`): `seed` 20261105, `gold_n` 60, `queue_n` 40, `cv_repeats` 5, `cv_folds` 5, `min_class_n` 5, `tfidf` (`sublinear_tf` true, `min_df` 3, `max_df` 0.5, `ngram_range` [1,2], `max_features` 20000), `svd_components` 100, `logreg_C` 1.0, `svm_C` 1.0, `gb_max_iter` 200, `gb_learning_rate` 0.05, `gb_max_depth` 4, `calibration` isotonic if every class in the fit has at least 20 examples else sigmoid, `calibration_cv` 3, `alpha` 0.05, `bootstrap` 2000.

1. **Normalise the free-text labels** (script function `normalise_evidence_type`, `normalise_design`). `evidence_type`: lowercase; contains `review` -> `review`; contains `case report` -> `case_report`; contains `mechanistic` or `experimental` -> `mechanistic`; contains `prognostic` -> `prognostic`; contains `associational` -> `associational`; else `descriptive`. Check: results in about descriptive 211, associational 130, review 40, case_report 19, mechanistic 19, prognostic 12 (counts approximate; print the actual mapping table into `run_notes`, with the raw-string to normalised count so the building agent can see ambiguous strings like `descriptive/associational` (-> `associational`, as mixed strings take the stronger claim) and `descriptive (experimental infection)` (-> `mechanistic`). `design` is free text with few repeats: normalise by keyword rules on `design` plus `include_type`: `include_type == 'case_report'` or contains `case report`, `single case` -> `case_report`; contains `review` or `include_type == 'review'` -> `review`; contains `experimental` or `challenge` or `inoculat` -> `experimental_infection`; contains `case-control`, `cohort`, `natural-infection`, `prospective`, `retrospective` -> `case_control_or_cohort_natural`; contains `survey`, `prevalence`, `cross-sectional`, `epidemiolog` -> `cross_sectional_or_prevalence`; contains `PCR`, `diagnos`, `assay`, `molecular`, `sequenc`, `genom`, `proteom`, `transcript` -> `diagnostic_or_molecular`; contains `treatment`, `therapy`, `trial`, `drug`, `efficacy` -> `treatment_trial`; else `other`. First match wins in that order. Print the resulting counts and 20 random mapped examples to `run_notes` (seeded) so a reader can check the rules; these normalised labels are themselves automatic and carry the same caveat.
2. **Stage A: sample the gold set and write the template.** Stratified sample of `gold_n` = 60 CB articles. Stratify on `primary_category` and period (2006-2012, 2013-2019, 2020-2026): allocate by category proportional to the square root of the category size, minimum 3 per category (NEU 8 and PUL 7 therefore contribute 3 each; if a category has fewer than 3 articles take all), then within a category spread across the three periods round-robin, drawing with `numpy.random.default_rng(seed)`. Oversample (at most 12 of the 60) from articles where `primary_category != agent_primary_category` and `category_confidence == 'low'`, so disagreement is covered; also include at most 6 reviews and 6 case reports so non-primary designs get examples. Record the stratum of each article. Write `data/experiments/EXP11-CORPUS-labels-gold-template.csv` with columns: `id,title,year,stratum,primary_category_auto,agent_primary_category,evidence_type_auto,design_auto,abstract_text,gold_primary_category,gold_secondary_tags,gold_evidence_type,gold_design,labeller,labelled_on,confidence,notes`. `abstract_text` is the Abstract Summary from the article note (not the existing automatic labels' reasoning). The three `*_auto` columns must be **omitted from the file given to the labeller** (the labeller must be blind to the automatic labels): write a second blind file `EXP11-CORPUS-labels-gold-blind.csv` without `primary_category_auto`, `agent_primary_category`, `evidence_type_auto`, `design_auto` and `stratum`, and give only that one to the labeller.
3. **Labelling (outside the script).** Preferred: a human (a veterinarian on the review). Alternative: an independent LLM agent, a fresh agent that has not seen the automatic labels, given only the blind CSV, the category definitions in 2.1, the closed sets for `gold_evidence_type` and `gold_design`, and the instruction to choose the one category the study is mainly about, to add up to 2 secondary tags, to give `confidence` as `high`, `medium` or `low`, and to write a one-line reason in `notes`. The labeller fills `labeller` (for example `human:<initials>` or `llm:<model id>`), `labelled_on` (ISO date), `confidence`. **LLM labels are a weaker gold than human labels**: they share training-data habits with the agents that produced `agent_primary_category` and `evidence_type`, so agreement with `agent_primary_category` is biased upward. Say which was used in `gold_set_summary.labeller_type` and in the interpretation. If both are available, a human relabels a random 20 of the LLM-labelled articles and Cohen's kappa between the two labellers is reported. Save the completed file as `data/experiments/EXP11-CORPUS-labels-gold.csv` (same columns as the blind file plus the answers; the script joins the `*_auto` fields back by `id`). The experiment is incomplete without this file; stage B refuses to run if it has fewer than 40 completed rows, and says so.
4. **Features.** (a) `embed`: `dbo.article.embedding` (1536 dimensions) or the local SVD substitute (record which). (b) `tfidf`: TF-IDF of the local-route text (title, one_sentence_finding, note summary sections, plus the first 1500 words of Results and Discussion where full text exists) using the defaults above, fitted inside each training fold only (no leakage). (c) `both`: hstack of `embed` (scaled to unit norm) and `tfidf`. Never include `primary_category`, `agent_primary_category`, `category_confidence`, `secondary_tags`, `aim` or `score_<CAT>` as features for the main comparison.
5. **Agreement of the current labels with the gold set** (for the gold articles): for `primary_category`, `agent_primary_category`, `evidence_type_norm`, `design_norm` against `gold_primary_category`, `gold_evidence_type`, `gold_design`: accuracy with Wilson 95% interval, macro F1 (classes in gold), Cohen's kappa with a bootstrap 95% interval (`bootstrap` resamples), confusion matrix (rows gold, columns automatic), per-class precision and recall, and agreement split by `category_confidence` high versus low (`primary_category` only). Primary-or-secondary agreement: share of gold articles where the automatic `primary_category` equals the gold primary or appears in the gold secondary tags. Gold-set n is about 60, so intervals are wide; report them.
6. **Classifiers.** For each target and each feature set (`embed`, `tfidf`, `both`) fit: multinomial `LogisticRegression(C=logreg_C, max_iter=2000, class_weight='balanced')`; `LinearSVC(C=svm_C, class_weight='balanced')` wrapped in `CalibratedClassifierCV(cv=calibration_cv, method=calibration)` for probabilities; `HistGradientBoostingClassifier(max_iter=200, learning_rate=0.05, max_depth=4, class_weight='balanced', random_state=seed)` on the SVD-100 projection of the features (fitted inside the fold). Also report a majority-class baseline. Logistic regression probabilities are also calibrated with `CalibratedClassifierCV` and the same settings.
7. **Cross-validation on the automatic labels.** `RepeatedStratifiedKFold(n_splits=5, n_repeats=5, random_state=seed)` over articles with a known automatic label. Group articles that share `cohort_id` in the same fold (use `StratifiedGroupKFold` with `cohort_id` as group, null `cohort_id` = its own group; repeat 5 times with `shuffle=True` and seeds `seed..seed+4`). Report per model and feature set: accuracy, balanced accuracy, macro F1, log loss, multiclass Brier score, expected calibration error (10 equal-mass bins on the top-class probability), mean and standard deviation over folds and repeats. Hyperparameters stay at the defaults (no tuning), so no inner loop is needed; if the building agent adds tuning it must nest it and say so. State the events-per-variable ratio as examples per class and per feature for the smallest class (NEU 8 and PUL 7 against hundreds of features: report it; classes below `min_class_n` merged). These scores are labelled `reproduces_automatic_labels`, not accuracy.
8. **Evaluation on the gold set.** Gold articles are held out entirely: refit each model on all non-gold articles with their automatic labels, predict the gold articles. For each model report accuracy, macro F1 and kappa against the gold labels with bootstrap intervals, and the paired comparison with the existing label: a McNemar exact test (binomial on the discordant counts) of model versus the automatic `primary_category` correct-versus-gold, with the number of discordant pairs. No multiple-testing control is claimed beyond Benjamini-Hochberg across the McNemar tests in the run (one family; `alpha` 0.05). Choose the best model per target by gold-set macro F1 for display, but state that selecting the best of 9 candidates on 60 articles is optimistic.
9. **Final predictions.** Fit the chosen model per target on all non-gold articles plus, if the gold set has at least 40 completed rows, on the gold articles with the gold labels weighted 5 (`sample_weight`; record the weight in `parameters`); predict all 444 articles with the calibrated top-class probability, the top-3 classes with probabilities, and the existing automatic label. For gold articles use the out-of-fold prediction so predictions are not trained on their own label.
10. **Active learning queue.** After step 9, from the non-gold articles rank candidates by uncertainty: `1 - margin` where `margin` is top-1 minus top-2 calibrated probability, using the category model; add `disagree_bonus = 0.25` if the model's top class differs from `primary_category`, `+0.25` if `primary_category != agent_primary_category`, `+0.1` if `category_confidence == 'low'`. Pick the top `queue_n` = 40 greedily with a diversity rule: at most 5 from one `primary_category` and at most 3 sharing a `cohort_id`; skip HU/BG and articles already in the gold set. Output `reasons` (the bonuses that applied) and the same blind-template columns as the gold template, so the queue can be labelled directly.

Seed handling: `numpy.random.default_rng(seed)` for sampling and bootstrap; `random_state=seed` for every estimator; fold seeds `seed + repeat`.

## 5. Acceptance checks

1. Stage A: the template has 60 rows (or all available if a stratum is exhausted), unique CB ids, no HU/BG, every `primary_category` present with at least min(3, size) articles; the blind file has none of the automatic label columns.
2. Stage B refuses to run with fewer than 40 completed gold rows and prints why.
3. JSON parses; `method` is `labels`, `dataset` null, `associations` and `cluster_assignments` empty; every kind in 4.1 present; `predicted_labels.rows` has 444 unique CB ids.
4. Reproducibility: two runs with the same seed give JSON identical except `run_utc`.
5. Leakage check: shuffle the automatic `primary_category` labels randomly (`--shuffle-train-labels` debug flag); cross-validated accuracy falls to about the majority-class baseline (within 0.05) and the gold-set accuracy is not above chance, else there is leakage.
6. Sanity: the existing `primary_category` agreement with `agent_primary_category` computed on all 444 equals 254/444 = 0.572 (190 differ); the normalised class counts sum to 444; the confusion matrix rows sum to the gold class counts.
7. The cross-validated metrics are titled as reproduction of the automatic labels in both the payload (`cv_scope`) and the interpretation; the interpretation states the labeller type.
8. Queue: 40 rows, none in the gold set, at most 5 per category, CSV row count equals the payload.
9. Load: `Babesiosis.Console --datasets-only` runs without error; `SELECT experiment_code, method FROM dbo.experiment WHERE experiment_code = 'EXP11-CORPUS-labels'` returns one row and `dbo.experiment_result` has 8 rows for it.

## 6. Caveats and reporting language

- Gold set about 60 articles: confidence intervals on accuracy and kappa are wide (about plus or minus 12 points on accuracy); small categories (NEU, PUL, END) have 3 gold articles each, so per-class recall is not estimable.
- LLM gold labels share biases with the LLM agents that produced `agent_primary_category`; agreement between gold and `agent_primary_category` is biased upward and must be reported as such. The best remedy is a human relabelling of a subset.
- Label definitions are unstable: a study can fairly be assigned several categories (secondary tags exist for that reason), so single-label accuracy understates agreement. Report the primary-or-secondary match next to it.
- Models trained on automatic labels learn their rules and errors. Model performance against the gold set is the only evidence of improvement. No classifier is described as clinically usable or as a replacement for review; they are screening aids.
- Normalised `evidence_type_norm` and `design_norm` are keyword rules on agent text and are themselves automatic.
- Articles are not independent: cohort grouping is used in cross-validation; CB510 and CB511 are one study published twice.
- Embeddings come from appraisal notes (many abstract-only). If the local TF-IDF substitute was used, say so.

## 8. Open questions

1. Who labels the gold set: a human or an independent LLM agent? Default: an independent LLM agent given only the blind CSV, flagged as a weaker gold, with a human relabelling of 20 articles when available. The building agent must not label the gold set itself.
2. Embedding route (SQL or local substitute). Default: try SQL, fall back to local TF-IDF + SVD, and state which.
3. `data/syndromes/` is absent on the machine where this spec was written; the `nlp_scores` feature set is therefore optional. Default: skip it.
4. Should `design_norm` be a target at all, given free-text designs and keyword rules? Default: yes, labelled as lowest-trust; drop it from the headline summary if more than 25% of articles land in `other`.
5. Should the gold sample be seeded from EXP10's review queue? Default: no, unless EXP10 has run; if it has, replace the oversampling quota of 12 with articles from its queue that have at least two reasons.
