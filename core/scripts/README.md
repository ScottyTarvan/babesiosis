# Scripts

Python 3 standard library only. Run from `canine-babesiosis-review/` with `python -I` (isolated mode, so nothing is imported from the data folders). Downloaded files are treated as data: they are parsed read-only and never executed.

| Script | Purpose |
|---|---|
| `search.py --start --end [--round rN]` | PubMed and Europe PMC searches, PubMed record fetch, deduplication, first-publication-date filter → `search/queries.jsonl`, `hits.jsonl`, `candidates.jsonl`. With `--round`, writes to `search/<round>/` instead and leaves out records screened in earlier rounds (listed in `candidates_prior_overlap.jsonl`); records that already have an article ID are kept and flagged `existing_id`. Also holds `load_rounds()` / `review_window()`, which read the rounds and windows from `search/rounds.json` |
| `citations.py --start --end [--round rN] [--registry-seeds \| --seed-file F]` | Backward/forward citation searching (Europe PMC) → `search/candidates_r2.jsonl`. Seeds are the include decisions in `--seed-file` (default `search/screening_r1.jsonl`), or with `--registry-seeds` every article in `articles.jsonl` with a PMID |
| `crossref_search.py --start --end [--round rN]` | Supplementary Crossref discovery → `search/candidates_crossref.jsonl`; `date_spread` flags records whose Crossref dates span more than a year (often retro-digitised archives) |
| `openalex_search.py --start --end [--round rN]` | Supplementary OpenAlex title/abstract search (keyless page paging) → `search/candidates_openalex.jsonl`; with `--round`, also the round-3 type and title filter → `candidates_r3.jsonl`, `openalex_filter_log.json` |
| `merge_candidates.py --round rN` | Merges a later round's candidate files (databases, citations, Crossref, filtered OpenAlex), deduplicated, with a `key` per record → `search/<round>/candidates_all.jsonl`, the screening input for that round |
| `build_screen_batches.py --round rN [--size 40]` | Screening batches for a later round, in the rounds 1–3 format, with notes on existing IDs, date discrepancies and unresolved citation records → `search/<round>/screen_batches/<round>_NN.md` and `batches.json` (the work list). The criteria are in `search/<round>/screening_criteria.md` |
| `assemble_screening.py --round rN --journal <path>` | Combines the three screening tiers (first screener, liberal rescue of every exclusion, senior adjudication of rescued and uncertain records) from the screening workflow's `journal.jsonl`, checks every key against `batches.json` → `search/<round>/screening.jsonl` |
| `build_clinical_rescreen.py [--size 40]` | Candidate set and batches for the clinical-syndrome-plus-treatment re-screen of excluded records → `search/clinical_treatment/candidates.jsonl`, `screen_batches/ct_NN.md`. Criteria: `search/clinical_treatment/screening_criteria.md` |
| `assemble_clinical_rescreen.py` | Merges `search/clinical_treatment/results/ct_NN.json` and `adjudications*.jsonl`, checks coverage and codes → `search/clinical_treatment/screening.jsonl`, `included.csv` |
| `build_clinical_tagging.py [--size 40]` | Tagging batches for the 444 included CB articles against the same clinical-syndrome-plus-treatment criterion (abstract from `search/packets/`, treatment sentences from `data/markdown/`) → `search/clinical_treatment/articles/candidates.jsonl`, `batches/ia_NN.md` |
| `assemble_clinical_set.py` | Merges `search/clinical_treatment/articles/results/ia_NN.json` and `adjudications*.jsonl` → `articles/tagging.jsonl`; joins with `screening.jsonl` (de-duplicated) → `search/clinical_treatment/combined_set.csv` |
| `repo_search.py` | Dataset repository searches (GEO, BioProject, Zenodo, Figshare, Dryad, PRIDE, MetaboLights, BioStudies, Dataverse) → `search/repo_*.jsonl` |
| `fulltext_checks.py <keys.txt> [out.jsonl]` | Europe PMC open-access full-text XML: data availability statements, supplements, repository links |
| `assign_ids.py` | Append-only stable IDs (`ids.json`) and per-article extraction packets (CB IDs and BG001). Reads rounds 1–3 from `search/` and later rounds from `search/<round>/` (`candidates_all.jsonl`, `screening.jsonl`, `duplicates.json`). A BG paper screened in by a later round gets a new CB ID (`replaces`); its BG entry is kept, retired, under `RETIRED:<BG ID>` with `source_key` and `replaced_by`. A retired record found again under another key gets a new CB ID, and its old entry gets `replaced_by`. Later-round packets also carry `replaces` and `duplicate_records` |
| `retire_ids.py [--ids ...] [--dry-run]` | After extraction: every record in `search/extraction_records.jsonl` decided `exclude_fulltext` or `unverifiable` gets `"retired": true` and `"retired_reason": "<decision>: <decision_reason>"` (reason cut to 300 characters, as in rounds 1–3) in `ids.json`. Entries already retired are left alone, so it is safe to re-run. Retired IDs drop out of `assign_ids.pending_articles()` |
| `fetch_datasets.py <spec.json>` | Downloads with 50 MB/file and 250 MB/total caps; SHA-256 provenance in `data/manifest.jsonl` |
| `fetch_fulltext.py [--all] [--ids ...] [--retry-failed]` | Tiered full-text retrieval (Europe PMC XML → OpenAlex PDF links → publisher landing pages) into `data/fulltext/<ID>/` (git-ignored); per-article state in `data/fulltext_status.jsonl`, attempts in `data/fulltext_log.jsonl`, manual-retrieval list and files to check by eye in `data/fulltext_missing.md`. Every file is title-checked (uses `pdftotext` for PDFs if installed). Re-runnable; hand-added PDFs are recorded as `manual`. Also covers assigned IDs not yet extracted (`assign_ids.pending_articles()`, `scope_label` "pending extraction"), so full texts can be fetched before extraction; a CB ID that replaces a reclassified BG ID takes over its file (`reused_from`). `to_markdown.py` and `abstracts_to_markdown.py` include the pending IDs too |
| `to_markdown.py [--ids ...]` | Full texts → sectioned Markdown in `data/markdown/<ID>.md` (git-ignored): JATS converted directly, PDFs via pymupdf4llm and cleaned; references and administrative back matter removed; YAML front matter with source, checks and quality flags; report in `data/markdown_report.md` / `.jsonl`. **Not stdlib-only:** run with `.venv/Scripts/python.exe -I` after `pip install -r scripts/requirements-markdown.txt` |
| `abstracts_to_markdown.py [--fetch]` | Abstract-only `data/markdown/<ID>.md` for articles without retrieved full text, so every article has a file: title, the authors' abstract (from the search packets/records; `--fetch` adds PubMed or the publisher page, cached in `data/abstracts_fetched.json`) and keywords; front matter `source_format: abstract`, `text_coverage`, MeSH terms. Never uses the review's own paraphrased summaries. `to_markdown.py` replaces a file once its full text exists |
| `finish_translations.py [--ids ...]` | English versions of non-English articles: takes LLM-translated bodies from `data/markdown/translations/<ID>.body.md`, applies the same heading and reference rules, checks numbers kept and length ratio, writes `data/markdown/<ID>.en.md` with translation fields in the front matter, and adds a translations table to `data/markdown_report.md`. Re-converting an original marks its translation stale. Also reads assigned IDs not yet extracted (`assign_ids.pending_articles()`). A text with no numbers counts as 100% kept; a body of fewer than 10 words beyond its title (a name or page range) skips the length and language checks |
| `extract_syndromes.py [--ids ...]` | scispaCy extraction over every article's Markdown (`<ID>.en.md` where present): bc5cdr disease NER + core scientific NER, abbreviation resolution, UMLS linking, NegEx negation; section-tagged mentions → `data/syndromes/mentions.jsonl`, `article_concepts.csv`, `concept_summary.csv`, `run.json`. **Python 3.12 env:** `.venv-nlp/Scripts/python.exe -I`, see `scripts/requirements-nlp.txt`; first run downloads the UMLS linker (~1.5 GB, cached in `~/.scispacy`), needs ~7 GB RAM |
| `build_term_display.py` | Curated dashboard display map for the per-article terms: ranks every CUI in `data/terms/*.json` by CB articles with an affirmed mention → `data/terms/term_display.csv` (`action` show/hide, `display_name` to merge or relabel, `note`). Manual columns are kept on re-run; only `concept` and `articles` are refreshed. Read by the console `TermLoader` |
| `categorise_articles.py` | Article categories from the extracted concepts: editable concept→category map (`data/syndromes/category_map.csv`, manual rows preserved), location- and IDF-weighted scores split into studied (title, abstract, methods, results) and mentioned only (introduction, discussion; studied for reviews), primary/secondary from the studied scores with SEV spread rule, mentioned categories, keyword-rule study aim (PREV, DIAG, BIOM, CLIN, CASE, TRT, PREVN, EXP, MOL, REV) → `article_categories.csv`; agreement with the agents' categories (not a gold standard) → `category_comparison.md`. **These are the review's categories:** `build_outputs.py` copies `nlp_primary` / `nlp_secondary` into `articles.jsonl` and the notes (agents' labels kept as `agent_*`, used only where the NLP finds none). The agreement report reads the agents' labels from `agent_primary_category` / `agent_secondary_tags` |
| `build_review_queue.py`, `evaluate_review.py` | **Retired (2026-10-28).** The human category review was dropped; the NLP categories are used as they are. Kept for the record; no step runs them |
| `export_article_terms.py` | Per-article export: categories, summary (from the note), one-sentence finding and every extracted term with its mention count, mapped category and studied/mentioned status → `data/syndromes/article_terms.jsonl` (complete) and `article_terms.csv` (spreadsheet). Run after `build_outputs.py` |
| `shortlist_severity.py` | Articles that test markers against clinical severity or outcome: severity/outcome sentences in the article's own sections from `mentions.jsonl`, marked "tested" when they carry an association or statistic, with biomarker-concept hints → `data/severity/candidate_sentences.jsonl`; ranked shortlist (tiers A–C; human comparators, reviews and single-case reports left out) with species and cohort → `data/severity/shortlist.csv`; seeds the editable marker map (canonical markers with class and matching pattern, plus scispaCy aliases; manual and extracted rows kept) → `data/severity/marker_map.csv` |
| `check_associations.py [--ids ...]` | Checks the LLM extractions in `data/severity/extractions/<ID>.json` (one row per marker × severity definition × subgroup × analysis; schema `data/severity/association_schema.json`, instructions `data/severity/EXTRACTION_GUIDE.md`): schema values, quotes found verbatim in the article text, numbers present in the text, marker normalised through the map → `data/severity/associations.csv`, `extraction_report.md` (problems, mappings to check, severity definitions, evidence preview), unmapped aliases appended to the map. With `--ids` it only prints the checks, for use by extractors |
| `inspect_files.py <DS...>` | Structure summaries of xlsx/docx/csv/zip/gz files → `data/inspection/` |
| `table_dump.py "<file>[::member]"` | Read-only viewer for sheets/tables (used by dataset-assessment agents) |
| `tidy_ds05.py` | Article 1 (DS05, BET cohort, CB126): the 'Entire population' and 'CORRESPONDENCE' sheets → `data/tidy/DS05.json` (dataset metadata and cleaning notes, variable dictionary with units, types, reference ranges and arithmetic parents, one subject per dog, long observations). Recodes sex, breed group, complaint flags, panting, mucous-membrane flags and the habitus score; keeps the authors' derived classes with `derived = true`. One such script per tidied dataset |
| `experiment_pairwise.py --dataset DS --code CODE --name N` | Pairwise associations over a tidy dataset: Spearman (numeric × numeric), Kruskal-Wallis / Mann-Whitney (categorical × numeric), chi-square with Cramér's V (categorical × categorical); permutation p values, Benjamini-Hochberg across the run; pairs where one variable is an arithmetic function of the other flagged `trivial`; Spearman matrix, average-linkage variable clusters and top findings as result payloads → `data/experiments/<CODE>.json`. **Not stdlib-only:** needs numpy (`scripts/requirements-experiments.txt`); run with `.venv/Scripts/python.exe -I` |
| `experiment_clustering.py --dataset DS --code CODE --name N` | Phenotype clustering of a tidy dataset (EXP02, DS05): log-transform of skewed variables, one iterative imputation, PCA with parallel analysis and varimax factors, Ward clusters with k chosen by silhouette (Gaussian mixture BIC and a parametric-null test beside it), bootstrap Jaccard and 80 percent consensus stability, cluster profiles in original units, cross-tabulation against the authors' classes (chi-square, Cramér's V, permutation p, Benjamini-Hochberg), five sensitivity analyses → `data/experiments/<CODE>.json`. **Not stdlib-only:** needs numpy, scipy and scikit-learn (`scripts/requirements-experiments.txt`); run with `.venv-nlp/Scripts/python.exe -I` (UMAP optional; PCA coordinates otherwise) |
| `experiment_anomaly.py --dataset DS --code CODE --name N [--raw-check FILE]` | Atypical admission profiles in a tidy dataset (EXP06, DS05): same 22 inputs and log1p rule as EXP02, one iterative imputation, isolation forest (1000 trees, mean of 10 seeds, seed stability) and robust Mahalanobis distance (MinCovDet), rank-normalised and averaged; the top 5 percent are labelled `outlier`; drivers (robust z, univariate isolation score, MCD contribution) for the top 10, the top 3 of each method and the pathogen-minority dogs; Spearman agreement with permutation p and bootstrap interval; sensitivity S1 to S4 (complete cases, no log, derived variables, suspect raw cells set missing). Reads the hand-written `experiment_specs/EXP06-raw-check.json` (raw-sheet findings; absent file = every status `pending`); `--selftest` injects haematocrit x10 and writes nothing → `data/experiments/<CODE>.json`. **Not stdlib-only:** needs numpy, scipy and scikit-learn; run with `.venv-nlp/Scripts/python.exe -I` |
| `build_datasets.py` | `datasets.jsonl` and per-article negative dataset checks (retired IDs skipped; round-4 records dated by their `search/r4/fulltext_checks.jsonl` check) |
| `render_datasets.py` | Priority ranks, independent-source groups and `datasets.md` |
| `build_outputs.py` | `articles.jsonl`, `index.md`, and late-bound cohort/dataset rows in article notes; categories from the NLP (`data/syndromes/article_categories.csv`), with `category_source`, `category_confidence` and the agents' labels as `agent_primary_category` / `agent_secondary_tags`; rewrites the notes' *Primary category* and *Secondary tags* rows |
| `synthesis_inputs.py <out_dir>` | Inputs for the category-synthesis agents, from the NLP categories in `articles.jsonl`: `search/synthesis/<CAT>_secondary_digest.md` (one line per secondary-tagged CB article), `inputs.json` / `args.json` (primary and secondary note paths per category), and in `<out_dir>` (outside the repo) condensed primary notes in parts of about 55,000 characters (`prim_<CAT>_partN.md`) and the cohorts and datasets per category (`ctx_<CAT>.md`). One Sonnet agent per category then rewrites `<CAT>.md` from these and the old file; Opus agents rewrite `CROSS.md` and `QUESTIONS.md` |
| `assemble_research_map.py` | `research-map.md` from the synthesis sections (`search/synthesis/<CAT>.md`, `CROSS.md`, `QUESTIONS.md`), comparator analysis and cohorts. The category table (article counts, independent cohorts, species, evidence types, datasets) is computed from `articles.jsonl` and the NLP categories |
| `build_search_log.py` | `search-log.md`: window and rounds from `search/rounds.json`; queries of every round; per later round a candidates-by-source narrative (databases, citations, Crossref, filtered OpenAlex, prior-round overlap, merged total) from `search/<round>/`; screening and extraction rows per round (duplicates merged at extraction counted apart); excluded and unresolved records listed with their round |
| `validate.py` | Syntax, duplicate identifiers, scope labels, links/backlinks/anchors, category totals, dataset-status consistency, checksums, absolute paths |

The tidy and experiment files are loaded into SQL Server by the console (`Babesiosis.Console --datasets-only`; tables `dataset`, `variable`, `subject`, `observation`, `experiment`, `association`, `cluster_assignment`, `experiment_result`; see `docs/database.md`).

Screening, extraction, dataset assessment, cohort linkage and synthesis were done by LLM agents orchestrated as workflows, for rounds 1–3 (2016–2026) and round 4 (2006–2016, completed 2026-10-28; brief in `search/r4/PIPELINE.md`). The categories come from the NLP scripts, with no human review; their inputs and structured outputs are kept in `search/` (`screen_batches/`, `screening_r*.jsonl`, `packets/`, `extraction_records.jsonl`, `dataset_assessments.json`, `human_comparators_raw.json`, `synthesis/`). Re-running the searches will return newer records; agent steps are not deterministic.

Typical rebuild after editing curated inputs:

```bash
python -I scripts/build_datasets.py && python -I scripts/render_datasets.py && python -I scripts/build_outputs.py && python -I scripts/export_article_terms.py && python -I scripts/assemble_research_map.py && python -I scripts/build_search_log.py && python -I scripts/validate.py
```
